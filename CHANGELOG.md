# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]
- Initial work on MongoZen.
- Fixed: only the first `SaveChangesAsync` of a session was ever transactional. `EnsureTransactionStartedAsync` returned early whenever a client session existed, and the client session outlives the commit, so every later save ran without a transaction; with `RequireTransactions = true` the second multi-group save in a session threw `TransactionRequirementException` on a server that supports transactions. Each save now starts (and commits or aborts) its own transaction on the same client session.
- Fixed: attachment writes could be silently lost on replica sets. `Attachments.StoreAsync`/`DeleteAsync`/`DeleteAllAsync` open the session's transaction, but `SaveChangesAsync` returned early without committing when no entity changes were tracked, so the transaction was aborted on Dispose. A save with nothing tracked now commits any pending attachment writes. `AttachmentTests` previously read back inside the writing session's own transaction and so could not detect this; they now verify from a fresh session.
- Changed: attachment reads (`GetAsync`, `GetNamesAsync`) no longer open a transaction. Doing so started the server-side transaction lifetime clock on a read and kept the transaction open until the next save.
- Changed: a failing `AbortTransactionAsync` on the save failure path no longer masks the original exception, and the abort is issued even when the caller's cancellation token has fired.
- Added: `ThrowIfDisposed` guards on all `Attachments` operations (the earlier changelog entry claimed them; they were missing).
- Test infrastructure: set `MONGOZEN_TEST_CONNECTION_STRING` to an existing replica set's connection string to run the Testcontainers-gated suite without Docker.
- CI: the pull-request workflow now also runs on `synchronize`, so pushing new commits to an open PR re-runs build and test.
- Fixed (serializer type coverage): `float`, `short`, `ushort`, `byte`, `sbyte`, `char`, `uint` and `ulong` properties were silently omitted from the written BSON and skipped on read. `TimeSpan`, `DateTimeOffset` and other framework structs were written as a nested document of their public properties and read back as `default`. `List<Guid>` elements were written as empty documents (the Guid converter was only registered in a unit test). `byte[]`, `List<SomeEnum>` and dictionaries with any value type other than `int`/`string` threw from the driver's root-level writer. All of these now have one implementation (`ElementCodec<T>`) shared by properties, array elements and dictionary values; the small integers map to Int32, `uint`/`ulong` to Int64, `float` to Double, `byte[]` to Binary, and the still-unsupported framework types throw a `NotSupportedException` naming the member path (e.g. `Order.Lines[].Discount (System.TimeSpan)`) on first use instead of losing data. The source generator reports the same cases as `MZ001`.
- Changed: null strings, collections, dictionaries and nested objects are written as BSON null instead of being omitted, and setting a nested object to null produces `$set: null` instead of `$unset`, matching the official driver and keeping the refreshed snapshot equal to the stored document.
- Changed: get-only (computed) properties are no longer serialized by the reflection tier (the generator and the official driver never did).
- Fixed: the id property is matched case-insensitively by both serializers, as `DefaultIdConvention` already did; a `public int ID` entity was stored under a server-generated `_id` and could never be loaded by its own id.
- Fixed (spurious updates): an entity diffed against its own fresh snapshot reported every `DateTime` with sub-millisecond ticks and every null string as changed, producing a `$set` (and an `_etag` bump) on every `SaveChangesAsync`. DateTimes are now written with exact integer millisecond arithmetic and compared at that precision; nulls compare equal to BSON null; a property missing from the snapshot is only set when it has a non-null value.
- Fixed: the identity map is keyed by (collection, id) instead of the raw boxed id, with numeric ids normalized to the entity's id type. Loading `User` 7 after `Order` 7 threw `InvalidCastException`; `LoadAsync<T>(4)` with an `int` against a `long` id created a second tracked instance.
- Changed: `Store` of a different instance under an already-tracked id throws `InvalidOperationException` instead of silently ignoring the second instance (which was then never saved). `Store` of the same instance remains a no-op. `Advanced.Store(entity, etag)` behaves the same instead of silently replacing.
- Fixed: `Store(x); Delete(x); SaveChangesAsync()` left `x` in the identity map, so a following `LoadAsync` returned the deleted instance.
- Fixed: the change tracker's own id index was keyed by `DocId` alone as well, so storing an `Order` 7 and a `Customer` 7 in one session made the second silently replace the first in the tracker and only one document was ever written. Entries now carry their collection id and the index is keyed by (collection, id); the per-save collection-name lookup per entity is gone as a side effect.
- Fixed: Hi/Lo refill published the new high before resetting the counter, letting a racing lock-free reader obtain an id that was then handed out again. The counter is reset first; at worst an id is skipped.
- Changed: Hi/Lo tag and identity-map collection are derived from the entity's runtime type, which is also the collection the change tracker writes to.
- `SaveChangesAsync` now writes through the driver's `BulkWriteAsync` (`InsertOneModel`/`UpdateOneModel`/`DeleteOneModel`) instead of hand-built `RunCommand` documents, so writes get the driver's retryable-writes handling across elections/stepdowns. Zero-copy insert/update payloads are preserved via `RawBsonDocument`.
  - Known limitation: an ordered bulk write outside a transaction can partially commit before failing; the change tracker isn't reconciled with what actually persisted, so a naive retry can hit duplicate-key errors on already-inserted docs. Documented in code where the bulk write is built; not yet fixed.
- Transaction-support detection now uses a real topology probe (`hello`/`isMaster`, checking for `setName`/`isdbgrid`) cached on `DocumentStore`, replacing brittle detection based on matching exception message text.
- `DocumentStore.Dispose()` now disposes the underlying `MongoClient` only when the store created it itself; a client passed in by the caller is left alone.
- Disposed-session guards are now consistent across `DocumentSession`'s public API (`Store`, `StoreAsync`, `Delete`, `LoadAsync`, `QueryAsync`, `AggregateAsync`, `CountAsync`, `AnyAsync`, `StreamAsync`, and the `Advanced`/`Attachments` operations) instead of only `SaveChangesAsync`.
- Added `IDocumentSession.StoreAsync<T>`, an async counterpart to `Store<T>` that awaits Hi/Lo ID refill instead of blocking the calling thread when the current range is exhausted.
- `StreamAsync`'s scratch arena is now reset after each cursor batch instead of growing unbounded for the life of the stream.
- Added Testcontainers-backed integration tests (opt-in, skipped when Docker isn't reachable) covering real transaction commit/abort, concurrency-conflict detection, and index conflict/recreate — paths the Mongo.Fakes-based suite can't exercise correctly since it isn't a replica set.
- `DynamicBlittableSerializer`'s collection/dictionary field detection is now structural (matches `IList<T>`/`IReadOnlyList<T>`/`ICollection<T>`/`IEnumerable<T>` and `IDictionary<K,V>`/`IReadOnlyDictionary<K,V>` by interface) instead of matching a fixed list of concrete generic types. Non-`List<T>`/`Dictionary<K,V>` collection-shaped types (e.g. Google.Protobuf's `RepeatedField<T>`/`MapField<K,V>`) are now recognized as collections/dictionaries on write instead of silently serializing as an empty-looking nested document.
  - Known limitation: read-side reconstruction still only special-cases arrays and `List<T>` explicitly; other concrete collection types fall back to converting a `T[]` to the target type, which throws for types with no array-compatible cast (e.g. `RepeatedField<T>`) instead of silently losing data as before — louder, but not yet a full round-trip fix.
